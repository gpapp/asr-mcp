# Boundary measurements, and what is still uncalibrated

**This replaces `docs/plans/boundary-and-voice-quality-plan.md`.** The plan is
gone; its measurements are not.

The original document was a 27-step improvement plan for boundary refinement and
new-voice learning, written 2026-10-01 from a review request (*"review how
boundaries are refined… also review new voice creation"*). P0–P4 shipped in
`c01b4fd`. What is left here is the part that cannot be regenerated by re-running
anything: **the measurements, the two things that did not work, and the four
thresholds that are still guesses.**

Everything that describes how the code works now lives in
[processing.md](processing.md) (pipeline, turns, boundaries) and
[voiceprints.md](voiceprints.md) (learning, pending, integrity, consolidation).
This file records why those decisions were made, not how to make them.

## What the P0 A/B measured

Before P0 there was no way to tell whether acoustic boundary refinement helped at
all. P0's job was to make it measurable, not to improve it.

Every internal turn boundary scored against the **raw Silero VAD sections** —
independent evidence of where speech actually starts and stops — as distance to
the nearest VAD edge, lower is better. No ASR involved, so the boundary decision
is isolated.

| clip | `acoustic: false` p50 / p90 / max | `acoustic: true` p50 / p90 / max |
|---|---|---|
| `0-four-speakers-zh` 56.9 s | 1.397 / 3.970 / 6.738 | **0.000 / 0.550 / 0.550** |
| `1-two-speakers-en` 16.0 s | 0.864 / 1.530 / 1.696 | **0.391 / 0.678 / 0.750** |
| `2-two-speakers-en` 34.0 s | 0.304 / 0.504 / 0.576 | **0.106 / 0.227 / 0.398** |
| `3-two-speakers-en` 54.8 s | 0.806 / 1.488 / 1.616 | **0.550 / 0.634 / 0.690** |
| **ZO249** 3439 s, 471 boundaries | 0.448 / 1.168 / 3.792 | **0.000 / 0.350 / 1.984** |

**Acoustic refinement wins on all five files, at every percentile**, by a wide
margin, and the margin is largest on the hardest material. So the engine was
*not* a no-op.

This also retracted an earlier claim. The original plan inferred a no-op from
"all 461 turns abut" — but abutting is the *designed* invariant of turn
preparation (lesson 17), because both refiners set `left["end"] = right["start"] =
cut`. It was not evidence of anything, and the inference was wrong.

`boundary_refine.acoustic: false` reproduces the first column and is the A/B
switch. `boundary_refine.enabled: false` rolls the engine back wholesale to gap
midpoints.

## Two results that do not flatter the work

**`spectral_change` never fired.** The `on` and `legacy` arms are byte-identical
on all five files, and `spectral_change` is the only difference between them. Its
two thresholds (`spectral_min_ratio`, `spectral_min_abs`) are reasoned defaults,
the only evidence for it is a synthetic pure-tone test, and on real material it
contributed **nothing**. It is kept because it is cheap and gated, not because it
is proven.

**The A/B arms do not isolate the router.** `acoustic: false` also makes step 7
(embedding-only) a no-op and downgrades step 13, so the arms produce *different
segment sets* — ZO249 gives 616 turns / 7 speakers off versus 472 / 4 on. The
per-boundary distance is comparable; the turn counts are not evidence of
anything.

**`inside_pct` had to be discarded as a metric.** The first scorer counted a
boundary sitting exactly *at* a VAD onset as a cut-through, producing a nonsense
"0.000 s median beside 65 % inside". Distance carries the conclusion;
`inside_pct` does not.

## The measurement that shaped the learning policy

The default ZO249 run learned `Pending 2026-09-30 19:43 Speaker_6 zo249` — 89
snippets / 606.13 s. Ranking six of that cluster's spans individually against all
35 registered profiles gave:

```
s6_0  19.5s  Alexander Radyukin 0.533  Nico Zeissig 0.573       margin 0.040
s6_1 547.6s  Alexander Radyukin 0.567  Marius Babrauskas 0.589 margin 0.022
s6_2 1142.5s Alexander Radyukin 0.589  Marius Babrauskas 0.611 margin 0.022
s6_3 1997.1s Gergely Papp      0.386  Alexander Radyukin 0.508 margin 0.122
s6_4 2737.3s Gergely Papp      0.531  Alexander Radyukin 0.533 margin 0.002
s6_5 3389.2s Gergely Papp      0.516  Alexander Radyukin 0.645 margin 0.130
within-group 0.175-0.291, between-group 0.368-0.448
```

That cluster was the guest in the first half **and** Gergely himself in the
second half. Naming it would have asserted one name for two people, and — because
both refinement sites consume a learned profile as a boundary reference — corrupted
the turn boundaries of every later run. The guest's nearest registered profiles
are all real colleagues, so the wrong name would have been *confidently* wrong.

Two numbers from here became the `learning` block's `0.32`: within-group 0.175–0.291,
between-group 0.368–0.448.

**Pitch cannot serve as a purity signal on this material.** `pitch_std` is 40–59 Hz
for *every* cluster including Gergely's own (57.3) — the f0 tracker produces
octave garbage here.

## Corrections to the original plan

Three claims in the plan were wrong by the time it was last read. They are
recorded rather than deleted, because each one explains a decision a reader would
otherwise re-litigate.

**Step 15 claimed the pending card shows a `purity` figure. It does not.**
`purity` is computed and stored — `db/models.py` carries the column, and
`voiceprint/service.py` populates it on the learn, extend and re-fit paths — but it
is rendered **nowhere**: not in `app.html`, not in the API layer. The retention
half of the step shipped; the surfacing half never did. This is still open.

**Step 15 described a policy that was later reversed.** It said *"fail closed: a
blend, or a split that cannot be verified, means do not learn."* That is no longer
the rule. `min_inter_dist` now **re-joins** groups into one part instead of
refusing them (lesson 46), because refusing discarded the largest speakers: 14
clusters were lost on `2026-10-07_17-00-32.mp4` at 0.175–0.281 apart, while two
profiles learned from that same file had *lower* intra-group means (0.170, 0.179).
The plan never recorded the reversal.

**A purity-max gate was tried and killed on real data.** `max_profile_intra_max`
existed briefly at 0.40, justified by a synthetic blend of two internally-perfect
voices (6 spans, mean 0.252, max 0.42). Real data ended it: `Speaker 9` on
`2026-10-07_17-00-32.mp4` is 20 spans, mean 0.255, max **0.463** — a speaker the
user had *already learned* scores higher on the maximum than the blend the gate
was built to reject, and the mean does not separate them either. No value of that
threshold admitted one and rejected the other, so it was removed. There is
deliberately **no** maximum-based gate on any group, re-joined or not.

One smaller correction: the plan's F6 listed
`matching.embed_only_accept_threshold` as dead configuration (one reference,
declaration only). It is now genuinely read, at `speaker/matcher.py`.

## What is still open

**1. `min_match_confidence` (0.60) is set from a single anecdote.** It rests on
one measured false positive — a 5 s turn of an unregistered speaker named at
confidence 0.539 — and `min_match_margin: 0.10` is **still unvalidated**: a
single-profile menu has no runner-up, so the margin gate has never been tested
against a real false positive at all.

Re-measuring it needs several **distinct unregistered** speakers, not corrupted
audio; the earlier calibration failed precisely by measuring the wrong
population. Until it is done, treat live per-turn naming as a bonus and the
shutdown re-attribution as authoritative — which is what the `thresholds.json`
comment already says.

**2. No fixture speaker-count table, so P2's effect is unquantified.** Learning now
reads *turns* rather than segments, and turns are coarser, so a cluster whose
segments all sit within `turn_merge_gap_sec` arrives as a single span →
`unverified:too_few_segments` → nothing learned, where previously it was. That is
fail-closed working as designed, but it can *reduce* learning on some material and
no run has quantified by how much. Rollback: `learning.fail_closed: false`.

**3. Four `learning` distances are all the same uncalibrated `0.32`**, taken from
the one podcast above. They are set to refuse rather than assert, so a wrong
constant loses a profile instead of inventing one. A second file with known
speaker counts would do more than another test.

**4. `spectral_change` should be calibrated or removed** (see above). Either move
`spectral_min_ratio` / `spectral_min_abs` against real gaps, or drop the method and
keep the four-step chain.
